Incident Brain

An incident agent that acts on a connected graph and shows how it got each answer.

During an incident, engineers drown in alerts and don't know which service is the cause or who to call. Incident Brain models the company as a FalkorDB graph of services, deploys, people, and past incidents, and an agent walks that graph to find the cause, the blast radius, and the right person to page. Agent decisions come from a scripted rule-based planner (mock mode); the LLM mode is built but has not been run live.

What we solved

  • Alert storms: many alerts reduced to a few incidents, grouped by shared dependency paths.
  • Likely cause: multi-hop traversal from the alerting service to recent deploys downstream.
  • Who to page: the active person with the most relevant work, with departed maintainers flagged.
  • Safety check: a proposed action is checked for rollback risk and held if risky.

How FalkorDB is used

Multi-hop DEPENDS_ON traversalblast radius, dependency pathsfind what is affected and why
algo.WCC (weakly connected components)alert correlationgroup alerts into incidents
algo.BFSblast tiersrank impact by hop distance
algo.CDLP (label propagation)failure domainsgroup services that fail together
algo.SPpathspath from alert to suspectshow the explainable path
Full-text indexesknowledge searchfind docs and decisions
Parameterised Cypherevery toolqueries are never string-built

If FalkorDB is removed, the agent cannot produce dependency paths or blast radius, so the graph is required, not decoration.
