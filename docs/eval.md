# Firefighter eval

> Generated by `python -m backend.agents.firefighter_eval` (mock mode: the deterministic planner; no LLM, no cost). Last run: 2026-10-16 18:07 UTC, 7.0 s. Raw results: `runs/eval/latest.json` (also `GET /api/eval/latest`).

Each scenario is a fixture applied to a fresh copy of one company in a twin graph `<tenant>__eval_<id>`: seeded, run, scored, deleted; the hero graphs are not used. The hand-written expectations are re-derived by an independent oracle (`seed/eval_oracle.py`: plain Python BFS, PageRank and the who-to-call formula over the fixture's own data, no Cypher, no agent tool) in `tests/test_eval_scenarios.py`.

**Profiles** (same planner, same loop, same report format, same grounding checks; only the tools differ):

- **Full Incident Brain** (`full`): every read tool: traversals, algorithms (PageRank, betweenness, shortest paths), full-text, memory
- **Graph, no algorithms** (`no_algo`): traversals and full-text only: no PageRank, betweenness, shortest-path or other algo.* procedure (removed: blast_tiers, connected_impact, correlate_alerts, dependency_path, failure_domains; shortest paths become plain Cypher; instead of PageRank, critical_services can only count how many services reach each one)
- **No graph (full-text + change log)** (`no_graph`): full-text search over docs, tickets and chats, the service catalog (name, owning team) and a flat change log (no dependency traversals, no algorithms)

A scenario passes when every incident has the right cause (deploy and service) and path, alerts are grouped into the right incidents, every false lead is rejected (not named, not rolled back, listed with a reason), the right active person (or, when nobody active owns the service, the team) is paged, nobody who left is paged, no wrong action is recommended (rollbacks and pages are checked per incident), no cause is also listed as a rejected lead, the hub pointer is right when nothing changed, and the report is grounded. The no-graph profile can never give a dependency path, so it can't pass a scenario that has a cause; its 'causes right' column is the fair comparison. 'Right person paged' is defined by the graph's who-to-call formula, so its deployer heuristic is at a structural disadvantage there too, and a wrong page counts both there and as a wrong action. Scenarios where the graph ALGORITHMS changed the outcome (full passes, no-algorithms fails): `k-storm`, `k-storm-hub`, `n-storm`. Everywhere else the plain traversals find the same answer; the algorithm calls there (shortest paths) only draw the path. Read the storm results carefully: the no-algorithms profile has no alert-correlation tool at all, so it pages per alert. At this size (27 services) a variable-length Cypher version of correlate_alerts would very likely match the algorithm version; what algo.BFS/algo.WCC buy is speed and bounded work at scale (docs/benchmarks.md).
