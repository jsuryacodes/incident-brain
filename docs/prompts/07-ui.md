Beats, in order:

## A. API additions the UI needs (check what M5 already has first; add only what's missing)

- `GET /api/meta`: tenants (id, display name, has_story), llm modes available, whether writes need a code, app version.
- `GET /api/story?tenant=`: story metadata generated by `backend/demo.py` (alert service for session 1 and 2, the
  labels for each button, resolver/summary for the resolve step). The frontend renders it and doesn't know it.
- Run events / replays: each Step event carries `seq, agent, action, tool, summary, cypher, params, result_preview,
  highlight {nodes[], edges[]}, cited[], writes {nodes[], edges[]}` (agent-written items, with `origin`), tokens/cost/mode.
  Edges are identified as `{source, target, type, props}`. Same shape for replay and fresh runs.
- `GET /api/subgraph?tenant=&ids=…&hops=1`: nodes + edges (with `origin`, label, display name, key props) for a set of
  ids. Used to prefetch everything a run will touch so the layout can be computed once.
- `GET /api/run-graph/{run_id}`: union of all nodes/edges any step of the run highlights or writes (for layout up front).
- `GET /api/compare/latest?tenant=`: the before/after numbers as JSON (tool calls until cause found for Session 1,
  Session 2, Session 2 without memory; cause found yes/no; recalled incident; who fixed it). Use the demo's own numbers.
- `GET /api/brain/suggestions?tenant=`: 6 suggested questions built generically from graph data (e.g. top PageRank
  service, a team name, a service with a departed maintainer, a stale doc). Templates are generic; values come from Cypher.
- `GET /api/explorer?tenant=&labels=&origin=`: tenant graph for the Explorer with a size cap (default services + teams +
  people; other labels on demand) and PageRank scores for node sizing.
- Story actions (resolve, session 2, compare) on the hero tenant: replay versions available to everyone; fresh-run
  versions require the access code (they write). Respect the existing caps.
- TestClient tests for every new endpoint, including the gate (no code → no writes) and tenant isolation.

## B. Frontend (`frontend/`)

Stack: current stable React + Vite + TypeScript, Tailwind CSS, zustand, lucide-react, Cytoscape.js + cytoscape-fcose,
@fontsource/inter + @fontsource/jetbrains-mono (self-hosted; no runtime CDN). EventSource for SSE. Vitest for unit tests.
No 3D. No heavy UI kits. Keep the bundle lean.

### B1. Theme system (light + dark), do this first
- Colours are CSS custom properties on `:root`, with `[data-theme="dark"]` overrides. Default = follow
  `prefers-color-scheme`. A header toggle cycles System → Light → Dark. Persist the choice in localStorage inside try/catch
  (works without storage). No flash of the wrong theme on load (inline script sets `data-theme` before paint).
- Starting tokens (tune for contrast; body text ≥ 4.5:1 and graph labels readable in BOTH themes):
  - Light: bg `#f6f6f4`, surface `#ffffff`, surface-2 `#f0f0ed`, text `#1b1c1f`, muted `#62656b`, border `#e2e2de`,
    path/accent `#2563eb`, alert `#dc2626`, memory (agent) `#b45309` stroke / `#fde68a` fill, ok `#15803d`.
  - Dark: bg `#0e1014`, surface `#151920`, surface-2 `#1c212a`, text `#e6e8eb`, muted `#8d939c`, border `#272c35`,
    path/accent `#60a5fa`, alert `#f87171`, memory (agent) `#fbbf24` stroke / `#4a3410` fill, ok `#4ade80`.
  - Agent lanes (not amber, not red): triage violet, investigator sky, communicator emerald — one shade per theme.
- **Colour meaning is fixed app-wide:** amber = written by an agent (memory). Red = the alerting service. Blue = the
  current step's path. Never use amber for anything else. Colour is never the only signal: agent nodes also get a small
  "AI" badge / double border; learned edges are dashed; the current path is thicker.
- The Cytoscape stylesheet is built from the computed CSS tokens and re-applied on theme change (no reload).
- Respect `prefers-reduced-motion` (no pulses, instant transitions).

### B2. App shell
Header: product name + simple glyph, view tabs (Story · Ask the Brain · Explorer), tenant switcher, mode badge
(Replay / Mock / Live), access-code button (opens a small dialog; code kept in sessionStorage only, sent as
`X-Access-Code`, never logged, never in the bundle), theme toggle, an "About" dialog (one paragraph, how it works,
the three tracks mapped to features, links to README/docs/repo). Desktop-first for 1440×900 and 1920×1080 (video);
below 1024px the panes stack and everything still works (judges may open it on a phone).

### B3. Story view (THE hero; build it first, make it great)
Three panes:
- **Left: agent timeline.** Step cards grouped in lanes (Triage / Investigator / Communicator) in order: tool name,
  one-line summary, small counter "tool call n" per agent. Handoff cards are prominent ("Triage → Investigator,
  via incident state"). Write steps show what was written (amber chip). The current card is highlighted; clicking any
  card jumps there.
- **Centre: graph.** Layout computed ONCE from `run-graph` (fcose, fixed seed, cached positions per run) so nothing jumps.
  The graph **grows** as the run progresses: start with the alerting service (red) and its neighbourhood; each step
  fades in the nodes/edges its receipt highlights; the current step's path is thick blue and the rest is dimmed; earlier
  steps stay visible but quiet. Agent writes appear in amber with one short pulse. **The learned DEPENDS_ON edge animates
  in as a dashed amber line drawing from source to target** — the money shot; make it unmistakable but tasteful.
  Labels: service names always; other nodes on hover/selection or when on the current path. Zoom/pan, "fit" button.
  Clicking a node opens its details in the right pane.
- **Right: receipt drawer.** For the current step: tool + why (summary), Cypher with syntax highlighting (a small
  custom Cypher highlighter is fine) and a copy button, params JSON, result preview, and **sources** as cards
  (label, title, excerpt in quotes, id). For a selected node: properties, origin, edges, sources.

Controls (bottom bar): Play / Pause, Step back / Step forward, speed 0.5× / 1× / 2×, a scrubber over the steps,
keyboard (space, ←/→). Autoplay is deterministic so the video can be re-recorded identically.

Story flow buttons (labels come from `/api/story`): **Fire alert** (Session 1) → **Resolve** → **Fire Session 2** →
**Compare without memory**. Default for visitors = golden replays; with access code = fresh mock runs. Ends on the
**before/after panel**: three columns (Session 1 / Session 2 with memory / Session 2 without memory): tool calls until
cause found, cause found?, recalled incident, who fixed it, industry match. Numbers come from `/api/compare/latest`.
Be honest in the labels: "Investigator tool calls until cause found" (as in progress.md decision 2).

Final report card at the end of each session: summary, likely cause + path, who to call (departed maintainer flagged),
decision with excerpt, "Seen before…", "Matches known industry pattern: … (link)", recommended actions, confidence, mode, cost.

### B4. Ask the Brain

not as errors. Without a code: answers work but are not persisted (show a small note).
